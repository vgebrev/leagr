# News Feed — first iteration implementation

Implements the News Feed ADR ([`202606211056-ADR-news-feed.md`](./202606211056-ADR-news-feed.md)): a chronological stream of session Preview/Recap cards derived on the fly from the momentum engine plus `rankings-YYYY.json` history. Display-only; no new data capture; the momentum maths is untouched.

## What was implemented

- **`src/lib/server/newsFeed.js`** (new) — pure derivation module:
    - `buildNewsFeed(players, {champions, ballers}, {asOf, competitionDays, maxThreads})` → cards newest first: one Preview card at the next competition date plus a Recap card per played session (≤ asOf).
    - `board(D)` semantics per ADR §6: player histories are bounded strictly `< D` and both momentum boards are built with `now = D` pinned, so a card reads identically before and after the session's own ranking update, and the `asOf` clock reproduces any past moment.
    - `nextCompetitionDate(asOf, competitionDays, playedDates)` — first unplayed competition-day date ≥ asOf (fallback: latest played + 7d).
- **Streak-outcome resolution** (the open design question from the ADR): the going-in streak comes from the bounded board; the outcome comes from applying the _same streak predicate_ to the player's session-D entry — `true` → **extended**, `false` → **broken** (at the going-in length), `null` (didn't feature / category unobserved) → **carriedOver**, and a going-in run of 1 turning true → **started**. No stored streak state is needed; unobserved-session skipping is inherited from the existing predicates.
- **Thread taxonomy (v1)**: `trophyStreak` / `spoonStreak` / `ballerStreak` (≥2, all outcomes; spoon `broken` carries the escape `position`; broken runs only reported at length ≥3 — a 2-run ending is churn, not news), preview-only momentum threads (`redHot`, `comeback`, `biggestMover`, `biggestFaller`, at most one per player per card, provisional players excluded), and recap-only **team result lines** (`teamLeague` with the match-points margin to the runner-up, `teamCup` with the beaten finalist and a `double` flag). Team lines replaced the original per-player `silverware` threads after user feedback: every player on the winning team got the line ("Cwenga wins the double", "Denzo wins the double"), which is team news wearing player clothes.
- **Stars of the Day (recap)** — a single reserved-slot item naming each baller category's winner for the session (MVP / Golden Boot / Playmaker / Brick Wall / Golden Glove), one line rather than one item per category. `starsOfTheDay(players, date)` takes the top `BALLER_CATEGORIES[].valueOf` per category. On a **tie it lists all co-winners** ("Brandon & Lunathi") — the live Stars of the Day board tie-breaks by "first to reach the count" (raw per-game order), which the session-total `stats` in the rankings history can't reconstruct, so the feed shows all level players rather than guess. Zero-contribution categories omitted. Reserved-slot like the team scorelines (always shown), scored `STARS_NOTABILITY = 1.95` to sit just under the team result.
- **Notability (v1 knobs)**: streak score = type weight × (1 + log2(length)) × outcome multiplier (broken 1.6 > started 1.3 > extended 1.0 > carriedOver 0.45); momentum threads score on magnitude in a sub-2 band. Team scorelines + Stars of the Day get **reserved card slots** (always shown) but rank below long streak stories per user feedback — a 5-session trophy run (3.99) or 7 straight Golden Boots outranks even a double (2.9/2.8). **`ballerStreak` weight raised to 1.5 (above trophy/spoon's 1.2)**: an individual award streak (one winner per category per session) is rarer and more meritorious than a team-shared trophy run, so a 2-session Golden Glove (3.0) now outranks the fortnightly crowd of shared trophy 2-runs (2.4). Top **12** threads per card (raised from 10 to make room for the reserved team + stars fixtures).
- **`src/lib/server/momentum.js`** — export-only refactor: `deriveTeamCounts` and `BALLER_CATEGORIES` exported; per-date award tops extracted into exported `deriveBallerTops()` (consumed by `buildBallersMomentum`, no behavioural change).
- **Preview roster gating** — the preview card describes the next upcoming session, so it is gated to the players **registered** for that session (available + waiting list), which live in the daily session file (`data/{leagueId}/{previewDate}.json` → `players`), _not_ the rankings history. `buildNewsFeed` takes a `registeredPlayers` option: an empty roster (nobody signed up / file absent) suppresses the preview card entirely; a non-empty roster filters preview threads to those players. Omitting the option (tests, momentum-only contexts) leaves it ungated. Exported `previewSessionDate(players, {asOf, competitionDays})` gives the next competition day.
- **Off-calendar (public-holiday) sessions** — a session can be scheduled on a non-competition day. Because `previewSessionDate` only knows the competition-day calendar, the API also scans actual session files: `earliestRegisteredSession()` finds the soonest upcoming session file (`date >= asOf`, not in rankings history) that has registrations. The preview date is `min(earliestRegisteredSession, nextCompetitionDay)` — so a registered holiday session on a Monday is previewed instead of being skipped to Saturday, while a far-future registration doesn't jump ahead of the imminent competition day. `buildNewsFeed` takes an explicit `previewDate` option to build the card for that resolved date.
- **Goal-difference on a points tie** — the league line's runner-up team, winner points, and points-margin come from rankings history. Goal difference does _not_ (the `teamGF/GA.perSession` in history are season averages, not that session's goals); it lives only in the session's match results. So when the top two are level on points, `buildNewsFeed` reports the GD margin from a `standingsByDate` map. The API's `tiedLeagueStandings()` detects tied dates from history (winner vs runner-up match points) and loads `StandingsManager.getStandingsForDate()` **only for those dates** (usually zero or one), not the whole season.
- **`src/routes/api/news/+server.js`** (new) — `GET /api/news?asOf=YYYY-MM-DD` (default today, clamped to today), standard non-public auth, gated on `momentum.enabled` (`{ cards: null }` when disabled), loads the asOf-year rankings and the upcoming session's registration roster (`data.get('players', previewDate, leagueId)`).
- **`src/routes/news/+page.svelte`** (new) — champions-page idiom (api singleton, `withLoading`, `titleParts`); renders `NewsCard`s with client-side "Load more" pagination (5 at a time); disabled-state empty view.
- **`src/components/NewsCard.svelte`** (new) — per-card date header, Preview/Recap chip, templated headlines per thread type/state/outcome (Preview voice = open questions, Recap voice = resolutions restating the setup), momentum-board icon vocabulary. **The clickable targets are the names, not the whole item**: `headlineSegments(thread)` returns the headline as text interleaved with `{player}`/`{team}` tokens, each rendered as a `role="button"` span. A player name opens `PlayerModal`, a team name opens `TeamModal`, both via `pushState('', { playerModal|teamModal: { name, date: card.date } })` (payload carries the card's session date so the modal shows that session's context). The `/news` page hosts both modals bound to `page.state`, mirroring the games/players pages. (Earlier the whole row was a button navigating to `/rankings/{player}`; that's gone.) Faint dividers between items; **broken-streak icons render grayed** (the badge fades when the run dies). A **league+cup double** is drawn as crown + trophy icons side by side (matching the momentum board's stacked-run vocabulary), not the combined `DoubleTrophyIcon`. The **Stars of the Day** line renders each category winner with its award icon (via the `lineIcon` snippet / dedicated branch). Team headlines name the runner-up and the numbers: "White Gorillas win the league with 13 points, 2 points clear of Orange Ninjas." / when the top two are level on points, "White Gorillas edge Orange Ninjas to the league on goal difference — both on 11 points (goal difference +3 to +2)." / "White Gorillas [also] win the cup, besting Green Panthers in the final [— for the double]."
- **`src/routes/components/TopNavBar.svelte`** — newspaper icon link to `/news` between the share button and settings (user's placement choice).

## Architecture decisions

- **Headlines rendered client-side** from structured thread data — the API stays pure data.
- **Per-card board rebuild** (≈27 dates × 2 boards × ~67 players) rather than a single-pass reuse: the pooled MAD and streaks are bound-dependent, and the cost is negligible (ADR §9).
- **Momentum threads only on Preview cards** — a recap's board is one beat behind by design (ADR §6), so "biggest mover" on a recap would describe the _previous_ session; recaps carry streak resolutions and the team scorelines instead.
- **No new settings key** — the feed inherits the `momentum.enabled` gate.

## Testing

- `test/lib/server/newsFeed.test.js` (39 tests, written first): frozen board(D) semantics (recap card deep-equal before/after later sessions exist), preview→recap flip, all four streak outcomes across trophy/spoon/baller threads, momentum-thread classification (fixtures verified against hand-computed EMA arithmetic), team result lines (margin, finalist, double flag, reserved slots), notability ordering (broken long run > extended short; long extensions > double scorelines), maxThreads capping, next-competition-date edge cases.
- Full suite green: 865 backend + 77 frontend; lint clean; production build passes.
- **Real-data smoke** (pirates 2026, script driving `buildNewsFeed` directly): the 2026-06-20 preview reproduces the ADR's example headlines ("Can Chris continue his 4-trophy streak?", "Jonathen looks to end a 3-session spoon run"); recaps read correctly (Jonathen actually sat out 06-20 — streak carried — then snapped it 06-27 with a double).
- **Rendered verification**: dev server + headless Chromium screenshots of `/news` (mobile and desktop widths) confirm cards, chips, icons, and navbar link render with real data.

## Assumptions / limitations (deferred to iteration 2)

- As-of clock **UI** (the API param already works); discovery teaser by the registration window (Players page); `breakout` thread; LLM prose; week-1 placeholder.
- Notability constants are declared tuning knobs — expect calibration against a few live weeks. Recap cards can still lean on concurrent trophy-run stories since team wins give 5-8 players identical streaks (the BROKEN_MIN ≥3 gate and team scorelines absorbed most of this; per-team streak aggregation remains a possible follow-up).
- The preview card doesn't know who has registered for the upcoming session — "players to watch" may include absentees.
