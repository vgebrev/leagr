# ADR: Game Timer — a refereeing clock in the Match Centre

- **Status:** Accepted (implemented 2026-07-25)
- **Date:** 2026-07-25
- **Scope:** Adds a countdown timer to the Match Centre: a league-level default game length, on-the-fly duration adjustment, pause/resume, a 3-second kick-off countdown, a synthesised referee's whistle with haptics, and support for the league's **"last play"** rule. Display and control only — **no match data is written**.

---

## Context

Saturday sessions are refereed off whoever's phone is handy, with no clock. Games are nominally 8 minutes, but there is no shared signal for kick-off or full-time, and the cup final actually runs 10 minutes — so game length must be both a configurable league default and adjustable in the moment, without a trip to the settings page mid-session.

The league also runs a **"last play" rule**: when regulation time expires, the team in possession gets one final chance. Play continues until (1) a goal is scored, (2) possession changes, or (3) one minute has elapsed.

That rule looks like it needs game-state awareness, and initially read as "probably too league-specific to build". It isn't, because of one observation that shrinks it dramatically:

> **The app cannot observe conditions 1 and 2.** A goal going in and a change of possession are the referee's judgment, made in real time on the pitch. Nobody is tapping the Match Centre's per-player action buttons mid-play — those get filled in after the whistle. Only condition 3, the one-minute cap, is mechanisable.

So conditions 1 and 2 collapse into a single "end play" tap, and last play becomes **a second, shorter countdown phase with an early-exit button** — reusing the same clock, the same anchoring, the same pause/resume and the same persistence as regulation time. It is one extra threshold and one extra button, not a new subsystem.

---

## Decision

### 1. Device-local, not synced

The timer runs in the browser of whoever is refereeing. State lives in a client-side singleton plus a `localStorage` snapshot; **nothing is persisted to match data**.

Rejected alternative — persisting timer state on the match object so every device sees the same clock — would require extending the league-match field whitelist (`src/lib/shared/validation.js:542-575`, which silently drops unknown properties), POSTing the entire `rounds` array on every control press, adding a polling loop (there is no websocket or SSE infrastructure), and correcting for client/server clock skew. Roughly 2–3× the work for a feature where, in practice, one person refs and everyone else can see the pitch.

**Accepted consequence:** two people can run independent clocks on the same match. This is not a defect; it is the cost of not building a sync layer for a problem that doesn't need one.

### 2. Wall-clock anchoring, not tick accumulation

Elapsed time is derived from an absolute epoch anchor, never accumulated from timer ticks:

```
elapsedMs = accumulatedMs + (runStartedAt ? Date.now() - runStartedAt : 0)
```

The tick interval's only job is to refresh a `now` value so the display re-renders. This is load-bearing rather than stylistic: mobile browsers clamp background `setInterval` to ≥1 s or suspend it entirely, so a tick-counting clock drifts badly on exactly the device this feature targets — a phone in a pocket. With an absolute anchor, drift is structurally impossible; when the tab wakes, `now` jumps to the truth and the clock is instantly correct.

The same `Date.now()`-bookkeeping approach is already used for pause/resume in `src/routes/year-recap/[year]/+page.svelte:271-292`.

It also gives free reload-resilience: because `runStartedAt` is absolute, restoring the `localStorage` snapshot after a page reload reconstructs the correct elapsed time with no extra logic.

### 3. One clock, two thresholds — phase is derived, not stored

Last play is **not** a separate status or a second timer. There is one clock and two thresholds:

```
hardStopMs  = durationMs + lastPlayMs          // lastPlayMs = 0 when the rule is off
phase       = elapsedMs < durationMs ? 'regulation' : 'lastPlay'
remainingMs = (phase === 'regulation' ? durationMs : hardStopMs) - elapsedMs
```

`phase` is **derived from elapsed time**, while `status` (`idle | countdown | running | paused | finished`) independently tracks the control state. Keeping the two orthogonal is what makes the feature cheap: pause/resume, wall-clock anchoring and the persistence snapshot all work identically in both phases, so an injury stoppage during last play needs no special handling at all.

Had `lastPlay` been modelled as a status instead, `paused` would have lost the information about which phase it was paused in — requiring a `pausedFrom` field and branching in every transition.

### 4. Signal design: length carries the meaning

Two whistle variants, distinguished by duration:

| Moment                                         | Signal                                      |
| ---------------------------------------------- | ------------------------------------------- |
| Kick-off (after 3-2-1), restart after pause    | **short** whistle (~350 ms) + short vibrate |
| Regulation time expires, last play is live     | **short** whistle + short vibrate           |
| True end of play (End Play tap, or cap expiry) | **long** whistle (~1200 ms) + long vibrate  |

A duration contrast reads more reliably across a noisy pitch than a pitch or timbre change would, and it needs no second synth voice. The referee's mental model is simple: **short means play continues, long means the game is over.**

Rejected alternatives: a distinct horn/buzzer at the regulation boundary (unambiguous, but a second synth voice for a distinction the length already carries); and a visual-only boundary (quietest, but the referee has to be looking at the phone at the exact moment time expires — which is precisely when they are watching the ball).

### 5. Synthesised whistle, not an audio asset

The whistle is generated with the Web Audio API: two oscillators at ~2400 Hz and ~2560 Hz (the detune beat is what makes it read as a whistle rather than a beep), an ~18 Hz LFO modulating both frequencies for the "pea" trill, a short filtered noise burst on the attack for breath, and a bandpass to keep it thin.

Chosen over shipping a `whistle.mp3` because it avoids sourcing audio of uncertain licensing, keeps a binary out of the repo, has zero download latency, and works offline — which matters, as the app has **no service worker and no PWA manifest**, so a static asset would be fetched cold on first play.

**Autoplay constraint:** the full-time whistle fires from a timer callback with no user gesture behind it, and would be blocked. The `AudioContext` is therefore resumed inside the Start tap — one unlock at kick-off covers every later signal in that session.

### 6. Last play is an opt-in league setting

Two flat settings, `lastPlayEnabled` (default **`false`**) and `lastPlaySeconds` (default `60`), alongside `gameDurationMinutes` (default `8`).

**Flat keys, not a nested `gameTimer: {…}` block:** `getEffectiveLeagueSettings()` performs a _shallow_ merge, so a nested block would lose its defaults on a partial write and need a bespoke deep-merge helper — which is exactly why `getEffectiveMomentumSettings()` had to exist. Three scalars sidestep the problem entirely.

**Defaulting to off keeps the deploy behaviour-neutral.** Last play is one league's rule, not a general 5-a-side convention; shipping it on would hand every other league a surprise extra minute they never asked for. With it off, existing leagues see a plain countdown that ends at 0:00 — exactly what a timer is expected to do — and the phase is a deliberate opt-in.

**Operational note:** `pirates` enables it in Settings → League Settings → Game Timer once deployed.

### 7. Duration overrides are ephemeral

The `−`/`+` control adjusts the current match only and stays live mid-run (that is the cup-final requirement). Navigating to another match resets to the league default, which falls out for free from the timer keying its snapshot on `${date}:${competition}:${round}:${match}` and resetting on a key mismatch.

Rejected alternative — a sticky per-day override in `localStorage` — solves a problem the league doesn't have: the 10-minute game is the single exception, not the pattern.

### 8. No admin gate

Timer controls follow the Match Centre's existing write-lock: everything is disabled once `isCompetitionEnded(date, $settings)` is true, exactly like the score inputs. No admin code, consistent with the fact that score entry on this page is already ungated — and with a device-local clock there is nothing to vandalise.

## Limitations

1. **Whistle punctuality depends on the page staying visible.** iOS Safari suspends hidden tabs entirely; Android Chrome throttles them, so a phone locked in a pocket may whistle late. Only the _audio_ is late — the clock itself is always correct, per Decision §2. Mitigated by a Screen Wake Lock while running and a catch-up whistle on `visibilitychange`. **Low impact in practice:** the timer is run by whoever is already keeping the session's stats, with the app open and the screen on for the whole session — so the degraded path is rarely hit.
2. **`navigator.vibrate` is not implemented on iOS Safari at all.** The call is guarded, so it is a silent no-op there; Android Chrome supports it after first interaction.
3. **The timer is device-local by design** (Decision §1). Independent clocks on the same match are expected behaviour.
4. **The synthesised whistle is an approximation** of a real whistle. Swapping in a sample later is a single-function change inside `whistle.js` plus a `static/` asset.
5. **Last play automates only the one-minute cap.** A goal or change of possession must be signalled by the referee tapping _End Play_. Attempting to infer either from the score or action buttons would misfire constantly, since those are filled in after play stops.
