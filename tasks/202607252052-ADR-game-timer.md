# ADR: Game Timer — a refereeing clock in the Match Centre

- **Status:** Accepted (implemented 2026-07-25; iteration 2 2026-07-26; iteration 3 2026-08-13)
- **Date:** 2026-07-25
- **Scope:** Adds a countdown timer to the Match Centre: a league-level default game length, on-the-fly duration adjustment, pause/resume, a 3-second kick-off countdown, a synthesised referee's whistle with haptics, and support for the league's **"last play"** rule. The running clock itself is never persisted to match data; the one thing that is, added in iteration 2, is a 0-0 scoreline marking a match as under way (Decisions §10–11).

---

## Context

Saturday sessions are refereed off whoever's phone is handy, with no clock. Games are nominally 8 minutes, but there is no shared signal for kick-off or full-time, and the cup final actually runs 10 minutes — so game length must be both a configurable league default and adjustable in the moment, without a trip to the settings page mid-session.

The league also runs a **"last play" rule**: when regulation time expires, the team in possession gets one final chance. Play continues until (1) a goal is scored, (2) possession changes, or (3) one minute has elapsed.

That rule looks like it needs game-state awareness, and initially read as "probably too league-specific to build". It isn't, because of one observation that shrinks it dramatically:

> **The app cannot observe conditions 1 and 2.** A goal going in and a change of possession are the referee's judgment, made in real time on the pitch. Nobody is tapping the Match Centre's per-player action buttons mid-play — those get filled in after the whistle. Only condition 3, the one-minute cap, is mechanisable.

So conditions 1 and 2 collapse into a single "end play" tap, and last play becomes **a second, shorter countdown phase with an early-exit button** — reusing the same clock, the same anchoring, the same pause/resume and the same persistence as regulation time. It is one extra threshold and one extra button, not a new subsystem.

---

## Decision

### 1. Device-local, not synced

The timer runs in the browser of whoever is refereeing. Clock state lives in a client-side singleton plus a `localStorage` snapshot; **no clock state is persisted to match data**. (Iteration 2 added one write triggered _by_ the timer — a 0-0 scoreline — but that is match data in its own right, not a clock: see §10.)

Rejected alternative — persisting timer state on the match object so every device sees the same clock — would require extending the league-match field whitelist (`src/lib/shared/validation.js:542-575`, which silently drops unknown properties), POSTing the entire `rounds` array on every control press, adding a polling loop (there is no websocket or SSE infrastructure), and correcting for client/server clock skew. Roughly 2–3× the work for a feature where, in practice, one person refs and everyone else can see the pitch.

**Accepted consequence:** two people can run independent clocks on the same match. This is not a defect; it is the cost of not building a sync layer for a problem that doesn't need one.

### 2. Wall-clock anchoring, not tick accumulation

Elapsed time is derived from an absolute epoch anchor, never accumulated from timer ticks:

```
elapsedMs = accumulatedMs + (runStartedAt ? Date.now() - runStartedAt : 0)
```

The tick interval's only job is to refresh a `now` value so the display re-renders. This is load-bearing rather than stylistic: mobile browsers clamp background `setInterval` to ≥1 s or suspend it entirely, so a tick-counting clock drifts badly on exactly the device this feature targets — a phone in a pocket. With an absolute anchor, drift is structurally impossible; when the tab wakes, `now` jumps to the truth and the clock is instantly correct.

The same `Date.now()`-bookkeeping approach is already used for pause/resume in `src/routes/year-recap/[year]/+page.svelte:271-292`.

It also gives free reload-resilience: because `runStartedAt` is absolute, restoring the `localStorage` snapshot after a page reload reconstructs the correct elapsed time with no extra logic.

### 3. One clock, two thresholds — phase is derived, not stored

Last play is **not** a separate status or a second timer. There is one clock and two thresholds:

```
hardStopMs  = durationMs + lastPlayMs          // lastPlayMs = 0 when the rule is off
phase       = elapsedMs < durationMs ? 'regulation' : 'lastPlay'
remainingMs = (phase === 'regulation' ? durationMs : hardStopMs) - elapsedMs
```

`phase` is **derived from elapsed time**, while `status` (`idle | countdown | running | paused | finished`) independently tracks the control state. Keeping the two orthogonal is what makes the feature cheap: pause/resume, wall-clock anchoring and the persistence snapshot all work identically in both phases, so an injury stoppage during last play needs no special handling at all.

Had `lastPlay` been modelled as a status instead, `paused` would have lost the information about which phase it was paused in — requiring a `pausedFrom` field and branching in every transition.

### 4. Signal design: length carries the meaning

Two whistle variants, distinguished by duration:

| Moment                                         | Signal                                     |
| ---------------------------------------------- | ------------------------------------------ |
| Kick-off (after 3-2-1)                         | **short** whistle (500 ms) + short vibrate |
| Regulation time expires, last play is live     | **short** whistle + short vibrate          |
| True end of play (End Play tap, or cap expiry) | **long** whistle (2000 ms) + long vibrate  |
| Restart after a pause                          | short vibrate only — no whistle (_it. 3_)  |

A duration contrast reads more reliably across a noisy pitch than a pitch or timbre change would, and it needs no second synth voice. The referee's mental model is simple: **short means play continues, long means the game is over.**

**A restart is not announced** (_iteration 3_). It originally blew a short whistle, matching what a referee does on the pitch, and that turned out to be the confusing signal of the set: from the pitch it is indistinguishable from a kick-off or from last play opening, and unlike those two it carries no information the players need — they can see the game restart. Only three moments are announced now, and each means something distinct. The buzz stays, as confirmation to the person holding the phone that the tap took.

Rejected alternatives: a distinct horn/buzzer at the regulation boundary (unambiguous, but a second synth voice for a distinction the length already carries); and a visual-only boundary (quietest, but the referee has to be looking at the phone at the exact moment time expires — which is precisely when they are watching the ball).

### 5. Synthesised whistle, not an audio asset

The whistle is generated with the Web Audio API: two oscillators at ~2350 Hz and ~2510 Hz (the detune beat is what makes it read as a whistle rather than a beep), a 20 Hz LFO modulating both frequencies for the "pea" trill, band-passed air noise running the length of the blast, and a soft-clipper.

**Loudness comes from saturation, not gain** (_iteration 2_). The voices are summed past unity and pushed through a normalised `tanh` waveshaper. Being bounded, it cannot clip the output however hard it is driven, while the flattened waveform raises average level far above what a bare sine reaches at the same peak. Measured with `OfflineAudioContext`, against the first cut: **+7.9 dB** RMS on the short whistle and **+6.8 dB** on the long, peak held at exactly the intended 0.92 with no clipping, and both blasts roughly doubled in length (0.35 s → 0.5 s, 1.2 s → 2.0 s).

The knob that matters most is `harmonicLevel`, and it is not the obvious one. Saturation already generates harmonics, so the explicit octave voice only tops them up — and at 0.22 it made the **octave the strongest partial**, dragging the spectral centroid to 4.5 kHz. Perceived pitch follows the strongest partial, so that reads as a smoke alarm rather than a whistle. Dropping it to 0.1 restores the 2400 Hz fundamental to dominance (centroid ~3.7 kHz) and costs **0.1 dB** — the loudness was never coming from that voice. A post-clipper lowpass was also tried and rejected: filter overshoot pushed peak to 1.152, i.e. it reintroduced the clipping the shaper exists to prevent.

The synthesis parameters live in one `WHISTLE` constants block at the top of `whistle.js`, since this is a thing judged by ear and expected to be re-tuned rather than restructured.

Chosen over shipping a `whistle.mp3` because it avoids sourcing audio of uncertain licensing, keeps a binary out of the repo, has zero download latency, and works offline — which matters, as the app has **no service worker and no PWA manifest**, so a static asset would be fetched cold on first play.

**Autoplay constraint:** the full-time whistle fires from a timer callback with no user gesture behind it, and would be blocked. The `AudioContext` is therefore resumed inside the Start tap — one unlock at kick-off covers every later signal in that session.

### 6. Last play is an opt-in league setting

Two flat settings, `lastPlayEnabled` (default **`false`**) and `lastPlaySeconds` (default `60`), alongside `gameDurationMinutes` (default `8`).

**Flat keys, not a nested `gameTimer: {…}` block:** `getEffectiveLeagueSettings()` performs a _shallow_ merge, so a nested block would lose its defaults on a partial write and need a bespoke deep-merge helper — which is exactly why `getEffectiveMomentumSettings()` had to exist. Three scalars sidestep the problem entirely.

**Defaulting to off keeps the deploy behaviour-neutral.** Last play is one league's rule, not a general 5-a-side convention; shipping it on would hand every other league a surprise extra minute they never asked for. With it off, existing leagues see a plain countdown that ends at 0:00 — exactly what a timer is expected to do — and the phase is a deliberate opt-in.

**Operational note:** `pirates` enables it in Settings → League Settings → Game Timer once deployed.

### 7. Duration overrides belong to their match

The `−`/`+` control adjusts the current match only and stays live mid-run (that is the cup-final requirement). A match not yet started opens at the league default.

_Superseded in part by §12 (iteration 3)._ As first built, moving to another match reset the override, which fell out for free from a single snapshot slot keyed on `${date}:${competition}:${round}:${match}`. With per-match clocks the override is part of the match's own stored clock, so stepping away and back returns the cup final's 10 minutes. Still ephemeral in the sense that matters: it is never written to league settings, and a fresh match never inherits it.

Rejected alternative — a sticky per-day override in `localStorage` — solves a problem the league doesn't have: the 10-minute game is the single exception, not the pattern.

### 8. No admin gate

Timer controls follow the Match Centre's existing write-lock: everything is disabled once `isCompetitionEnded(date, $settings)` is true, exactly like the score inputs. No admin code, consistent with the fact that score entry on this page is already ungated — and with a device-local clock there is nothing to vandalise.

### 9. Its own panel, and monochrome

_Iteration 2._ The timer is a sibling glass panel sitting between the score card and the team action panels, rather than a bordered strip inside the score card as first built. It is a distinct instrument, not an attribute of the scoreline, and at the top of the stats-capture area it falls under the thumb where the referee is already tapping.

Colour is spent only where it encodes an affordance: the progress bar and the buttons keep the accent, everything else is the standard light/dark grays. The first cut tinted the clock amber under 60 s and red under 10 s, and the LAST PLAY and FULL TIME labels to match. That was dropped — the two team panels are already saturated blocks of team colour, so a third colour vocabulary in between read as noise rather than urgency, and the clock digits plus the bar already carry "nearly out of time" without it. The LAST PLAY label keeps its `motion-safe` pulse, which now does the attention-drawing that amber used to.

**Collapsed by default, expanding to the full controls.** The binding constraint is that the score, the stats, the timer and the per-player capture buttons all have to fit on one phone screen without the layout shifting mid-match. So the timer's resting state is a single row — a `Timer` label, the clock centred in the panel at `text-xs` (the same size as the status badge, since at a glance the referee is reading position on a progress arc more than digits), and the LAST PLAY / FULL TIME badge pulled right against a bare icon button for the one control that matters while a game is running. Expanding reveals the duration stepper, the badge, mute, the clock again at `text-2xl`, the progress bar, and the labelled Start/Pause/Resume/End Play and Reset buttons.

Centring in both states is done by giving the flanking groups `flex-1` rather than by `justify-between` or `ms-auto`: equal shares of the free space put the clock at the true centre of the panel, and the badge at the true centre between the stepper and mute, even though those flanks differ in width by 4×.

It follows the `StatsGuide` idiom: a borderless chevron on the left that rotates 90°, a fixed `Timer` label beside it, and a `transition:slide` body. **The chevron and the label are the only things that hold their place** — they anchor the panel, which frees the clock and its status badge to move into the body and grow when expanded, rather than being pinned to the header for the sake of continuity. An earlier cut kept the clock in the header across both states; it made the expanded layout lopsided for no real gain, since the anchor is what stops the panel feeling like it jumps, not the clock.

Both states render the clock and badge from shared snippets parameterised only by text size, so they cannot drift apart. Likewise the primary control exists in exactly one place at a time — icon-only in the header when collapsed, labelled in the body when expanded — with `primaryLabel`/`PrimaryIcon`/`primaryDisabled` derived once and shared. (Iteration 3 adds a second control beside it during last play; see §13.)

`expanded` is persisted per device next to `muted`, so the choice survives navigating between matches. Like mute, the toggle stays live when `isCompetitionEnded` locks the panel: it is a view preference, not a match write.

### 10. Starting play opens the scoreline at 0-0

_Iteration 2._ Starting the clock, or recording any stat on a match with no score, writes `homeScore: 0, awayScore: 0` through the ordinary score-saving path (`gamesService.startScoring()` → the same `/api/games` POST the score inputs use).

A `null` score means "not played"; `0-0` means "played, nobody scored". Without this, a goalless game is indistinguishable from one that never happened, and the distinction has to be made by hand after the fact. Both triggers are moments where the app has just learned that play is happening, so it is the cheapest possible place to record it.

The write is guarded to fire only when both scores are `null`, which makes it idempotent: a restart after Reset, or a second stat, does not re-post. Nothing clears the scoreline back to `null` — Reset returns the clock to 0:00 but leaves the score alone, since the game did happen.

### 11. A stat on an unplayed match starts the clock — silently

_Iteration 2._ Recording a stat on a match whose score is still `null` also starts the clock, via `startLate()`: straight to `running`, with **no 3-2-1 and no kick-off whistle**.

This covers the tracker forgetting to hit Start, or the game being timed off-app. The `null` → `0-0` transition is a good kick-off signal precisely because it happens exactly once per match, so there is no risk of a later stat restarting a clock the referee has deliberately reset.

Suppressing the countdown and the whistle is the important half of the decision. Both announce a kick-off, and by the time a stat exists the kick-off has demonstrably already happened — a 3-2-1 mid-play is worse than silence. `startLate()` still runs `unlockAudio()` inside the tap, so full time remains audible.

**Accepted consequence:** the clock reads late by however long it took to record that first stat, and so does the full-time whistle. Judged the better failure: in 5-a-side the first stat lands early, and an approximate clock beats none at all. A referee who wants it exact still has `−`/`+` and Reset.

Rejected alternative — not auto-starting — keeps the clock honest but leaves the forgot-to-start case with no clock whatsoever, which is the failure this was raised to fix.

### 12. Every match keeps its own clock

_Iteration 3._ `localStorage` holds a map of clocks keyed by match key rather than a single record, and `attach()` restores the incoming match's clock instead of resetting on a key mismatch. **A clock is only ever reset by the referee** — Reset, or starting a fresh match that has no stored clock.

The behaviour this replaces was a real defect: the next/previous buttons at the foot of the Match Centre destroyed a running clock, and because the one snapshot slot was immediately overwritten, navigating back could not recover it. Stepping to the previous match to check a scoreline is an ordinary thing to do mid-session, and it should not cost the clock.

**One clock per match rather than one clock, labelled.** The alternative was to keep a single live clock that navigation never rebinds, showing it on every match with a note saying which match it belongs to. That models the referee (one person, one clock) more literally, and it would keep whistling while you look at another match. It was rejected as the more confusing surface: a panel showing another match's clock invites mis-taps, and it needs a "free this clock" affordance that per-match storage doesn't.

**Accepted consequence:** a clock left running on another match is not ticking, so its full time does not sound until you come back to it — at which point the restore path fires one long whistle and parks it at Full Time. The clock reading itself is never wrong, because it is wall-clock anchored (§2).

Storage is bounded by dropping clocks older than 12 hours and capping the map at 12 entries, most recent first, with the match being played never evicted. Pruning is by age rather than by date prefix so that opening an old session's Match Centre cannot wipe the clocks of the session in progress. A clock stored in the old single-record format is migrated on read.

Separately, `detach()` no longer stops a live clock: leaving the Match Centre for the standings keeps it ticking and audible, and only `destroy()` is a hard teardown.

### 13. Last play gets its own button

_Iteration 3._ End Play is a second button to the left of the primary, shown only during last play. The primary stays Start / Pause / Resume in every phase.

As first built, End Play _took over_ the primary slot, which left no way to pause during last play — an injury in the final minute could only be dealt with by ending the match. It also created a dead end: a clock paused in regulation whose duration was then shortened past the elapsed time read "End Play" with no way to resume, because `isLastPlay` is true while paused (§3).

Keeping the primary's meaning fixed matters more than putting the decisive action under the thumb: the button the referee's thumb is already resting on must not change function the instant regulation expires. The two are separated by weight rather than by hue — End Play is an outlined primary button against the solid one, with a `StopSolid` icon against the pause bars. A red button was tried first and dropped: it spends a colour the panel otherwise reserves for the progress bar and the accent (§9), and it read as a warning rather than as the ordinary way a last play ends.

## Limitations

1. **Whistle punctuality depends on the page staying visible.** iOS Safari suspends hidden tabs entirely; Android Chrome throttles them, so a phone locked in a pocket may whistle late. Only the _audio_ is late — the clock itself is always correct, per Decision §2. Mitigated by a Screen Wake Lock while running and a catch-up whistle on `visibilitychange`. **Low impact in practice:** the timer is run by whoever is already keeping the session's stats, with the app open and the screen on for the whole session — so the degraded path is rarely hit.
2. **`navigator.vibrate` is not implemented on iOS Safari at all.** The call is guarded, so it is a silent no-op there; Android Chrome supports it after first interaction.
3. **The timer is device-local by design** (Decision §1). Independent clocks on the same match are expected behaviour.
4. **The synthesised whistle is an approximation** of a real whistle, and has been tuned by measurement rather than by ear — level, duration and spectral balance are all verified, but nobody has confirmed it _sounds_ right. Swapping in a sample later is a single-function change inside `whistle.js` plus a `static/` asset.
5. **Last play automates only the one-minute cap.** A goal or change of possession must be signalled by the referee tapping _End Play_. Attempting to infer either from the score or action buttons would misfire constantly, since those are filled in after play stops.
6. **A late-started clock is late** by the delay before the first stat was recorded, and its full-time whistle with it (Decision §11). Deliberate.
7. **A clock parked on another match is silent.** Per §12 only the attached clock ticks, so a game left running while the referee looks at a different match whistles full time late, on return. The reading is always correct; only the signal waits.
8. **A seeded 0-0 is never withdrawn.** Recording a stat on the wrong match leaves that match reading "played, 0-0" rather than unplayed, and the only way back is the score input — clearing it to blank restores `null`. Taking the stat back does not, because a decrement is treated as a correction rather than evidence of play, so it never seeds in the first place.
